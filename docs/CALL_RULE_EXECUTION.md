# 通话规则自动执行

通话页从“正在拨号”开始。有头像和无头像共用一套状态名称、时长及音频规则。入口、下一状态和按钮跳转由程序决定。号码仍可选择提示类型、音频池和接通后的自动挂断时间。

普通呼叫依次经过“正在呼叫 → 等待接听 → 通话中”。通话结束后进入“正在挂断 → 已挂断”，保存记录并返回。提示类号码按“正在呼叫 → 等待接听 → 对应提示状态 → 正在挂断 → 已挂断”推进。默认先拨号 2 秒，普通号码等待接听 8 秒。勾选“提示类号码使用默认等待时长”时，关机、空号和忙线号码改为静音等待 1 秒，无法接通号码静音等待 3 秒，然后播放四遍提示音。旧配置中的入口和跳转字段会继续读取，但不会改变上述流程。

## 执行约定

- 状态设置正数时长后，到时按程序设定的顺序切换。
- 时长为 0 时不按时间推进；呼叫或等待阶段的音频完整播放后可进入下一状态。接通与保持状态会继续停留，直到挂断或其他通话操作。
- 正在挂断与已挂断会完成清理；这两个状态设为 0 秒时立即推进或结束。旧配置缺少必需状态时自动补齐。
- 明确配置的状态时长优先于音频结束；音频不能擅自提前结束当前步骤。
- 合并旧配置时保留仅在一套规则里修改过的状态，冲突时以无头像规则为准。两套里未修改的状态使用新默认值。
- 号码单独绑定的“接通后自动挂断”仍会在设定秒数到达时挂断，可早于“通话中”的状态时长。
- 后台不再暂停规则计时；返回界面时显示执行器的当前步骤。
- 点击通话界面底部的空白区域会执行“对方挂断”规则，震动一次并保存通话记录。显示文字固定为“通话结束”，停留时长和音效可单独调整，默认停留 1 秒。

## 操作中断

保持切换、手动挂断及号码自动挂断通过统一执行器切换。静音、扬声器与拨号盘开关不改变当前规则的截止时间。

每次进入状态都会产生新的执行序号，包括重新进入同一状态。旧的倒计时、音频完成、彩铃视频与语音回调只对原步骤有效；步骤被替换后不能再把流程带回原分支。旧步骤的循环音频、一次性音效和视频随步骤退出释放。

## 验证

`CallRulesTemplateTest` 检查旧入口和跳转配置被固定流程覆盖，`CallRuleExecutorTest` 检查普通流程、提示分支、用户设定的各阶段时长、0 秒结束与不计时的接通状态。`bash gradlew :app:testDebugUnitTest :app:assembleDebug --offline` 通过。

调度器每次唤醒会重新核对剩余时间，直到到期或当前步骤被取消；旧步骤的倒计时、音频和视频回调不能恢复已退出的分支。

在已连接的 Pixel 4 XL 真机上安装调试包，`CallRulePersistenceRuntimeTest` 使用独立内存数据库验证同一套时长保存后能被两种通话界面读取，没有修改用户配置或拨打真实电话。Compose 界面测试在这台设备上因测试框架调用缺失的 `InputManager.getInstance` 而无法运行。
