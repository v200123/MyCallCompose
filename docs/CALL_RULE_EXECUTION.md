# 通话规则自动执行

通话页从“正在呼叫”开始，按程序设定的状态顺序推进。用户可以分别调整有头像和无头像界面的状态名称、时长及音频播放次数；入口、下一状态和按钮跳转不由用户设置。号码仍可选择提示类型、音频池和接通后的自动挂断时间。

普通呼叫依次经过“正在呼叫 → 等待接听 → 通话中”。通话结束后进入“正在挂断 → 已挂断”，保存记录并返回。提示类号码按“正在呼叫 → 等待接听 → 对应提示状态 → 正在挂断 → 已挂断”推进，每个状态都使用规则页设定的时长。旧配置中的入口和跳转字段会继续读取，但不会改变上述流程。

## 执行约定

- 状态设置正数时长后，到时按程序设定的顺序切换。
- 时长为 0 时不按时间推进；呼叫或等待阶段的音频完整播放后可进入下一状态。接通与保持状态会继续停留，直到挂断或其他通话操作。
- 正在挂断与已挂断会完成清理；这两个状态设为 0 秒时立即推进或结束。旧配置缺少必需状态时自动补齐。
- 明确配置的状态时长优先于音频结束；音频不能擅自提前结束当前步骤。
- 规则页随已保存配置更新，切换有头像和无头像规则时分别读取对应配置。
- 号码单独绑定的“接通后自动挂断”仍会在设定秒数到达时挂断，可早于“通话中”的状态时长。
- 后台不再暂停规则计时；返回界面时显示执行器的当前步骤。
- 自动进入通话中不会弹出麦克风权限请求，语音挂断仍可通过页面按钮自愿开启。

## 操作中断

保持切换、手动挂断、语音口令及号码自动挂断通过统一执行器切换。静音、扬声器与拨号盘开关不改变当前规则的截止时间。

每次进入状态都会产生新的执行序号，包括重新进入同一状态。旧的倒计时、音频完成、彩铃视频与语音回调只对原步骤有效；步骤被替换后不能再把流程带回原分支。旧步骤的循环音频、一次性音效和视频随步骤退出释放。

## 验证

`CallRulesTemplateTest` 检查旧入口和跳转配置被固定流程覆盖，`CallRuleExecutorTest` 检查普通流程、提示分支、用户设定的各阶段时长、0 秒结束与不计时的接通状态。`bash gradlew :app:testDebugUnitTest :app:assembleDebug --offline` 通过。

调度器每次唤醒会重新核对剩余时间，直到到期或当前步骤被取消；旧步骤的倒计时、音频和视频回调不能恢复已退出的分支。

在已连接的 Pixel 4 XL 真机上安装调试包，`CallRulePersistenceRuntimeTest` 使用独立内存数据库验证有头像、无头像两套时长保存后均能被拨号流程读取，没有修改用户配置或拨打真实电话。Compose 界面测试在这台设备上因测试框架调用缺失的 `InputManager.getInstance` 而无法运行。
